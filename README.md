# 盲审分配台 · Blind Review Desk

一款在 **浏览器本地** 完成稿件—评审人自动分配的 Web 应用。无需后端、无需注册，所有数据只保存在你自己的浏览器（localStorage）中，分配计算由 [javascript-lp-solver](https://www.npmjs.com/package/javascript-lp-solver) 以整数线性规划（ILP）在页面内完成。

技术栈：**React 18 + TypeScript + Vite + javascript-lp-solver**。

## 功能

- **录入稿件**：标题、所需评审人数、主题标签（可多个），并可为每篇稿件指定 **0 至所需人数位“预指派”评审人**。
- **录入评审人**：姓名、**机构**、擅长标签、审稿容量（最多承担稿件数）、利益冲突（勾选需回避的稿件）。
  - **机构去重（硬约束）**：机构值**去除首尾空白后完全相同**者视为同一机构（区分大小写）；生成分派与确认互换后，**同一篇稿件至多选择每个机构一人**。
  - 机构**留空**表示无机构：空值仅代表该评审人本人，**不与其他空值合并**——多位空机构评审人可以评审同一篇稿件。
  - 该约束与利益冲突、容量、所需人数、预指派**共同求解**；可行性预检（Dinic 残量最大流）与正式 ILP 求解遵循同一规则。
  - 若**预指派已让同一篇稿件出现重复机构**（同一非空机构 ≥2 位预指派评审人），「生成分派」将**整体拒绝**、不返回任何部分结果，并在结果区逐条列出**稿件、机构与相关评审人**。
- **预指派（硬约束）**：在**稿件**编辑区为每篇稿件指定 0 至需求人数位评审人；生成分派时这些（稿件，评审人）关系与其余硬约束**共同求解**，被指定者必定入选，其余名额仍按主题匹配与负载均衡优化。
  - 预检逐条拦截并在结果区以表格列出**具体稿件、评审人与原因**：引用的稿件/评审人已不存在、与利益冲突冲突、同篇预指派超过名额、单人预占超过容量；
  - 任一预指派问题存在时**整体中止，不生成任何部分结果**；
  - 删除或修改稿件/评审人（含新增利益冲突、调整容量/名额）后，**失效关系不会被静默删除**：稿件页底部“待处理的失效预指派关系”区会显式提示每条原因，可**逐条移除**，数据恢复后关系自动重新生效；
  - 成功结果与 JSON 导出中，来自预指派的分派带 **📌 预指派 / `preassigned`** 标记（汇总含 `preassignedCount`）；
  - 「分派互换」不会换走任何预指派分派（候选枚举与应用时双重排除）。
- **一键生成**：先严格满足全部硬约束，再做目标优化。默认生成 **1 个方案**（保持原有行为）。
- **备选方案模式（1～3 个方案）**：在顶部「生成分派」旁选择方案数 2 或 3，并输入最小差异条数 **N**：
  - **方案 1 仍为字典序最优**（先最大化主题匹配、再最小化最大负载），与单方案模式完全一致；
  - 方案 2、3 必须满足**全部硬约束**（预指派 / 利益冲突 / 容量 / 人数 / 机构去重），并且与**已生成的每个方案**至少有 N 条不同的稿件—评审人关系；
  - “不同关系条数”按两个方案分派集合的**对称差**计算（一方多出的关系 + 另一方多出的关系；两方案名额数相同，故恒为偶数——输入奇数 N 时按不小于 N 的最小偶数生效）；
  - 预指派关系在所有方案中必须相同，因此差异上界为 `2 ×（总名额 − 预指派条数）`，N 输入超界时按钮禁用并提示；
  - **无法凑满数量时不报错**：保留已找到的全部方案，并在结果页横幅说明停止原因（在全部多样性约束下第 k 个整数规划不可行）；
  - 结果页用**标签切换**方案，每个标签直接对比**主题匹配数、评审人最大负载、相对方案 1 的差异条数**；
  - 「导出结果 JSON」导出的是**当前选中的方案**，文件中写入方案序号 `solution.index`、本次方案总数 `solution.total`、N（`solution.minDifference`）与相对方案 1 的差异条数（`solution.diffToFirst`）；
  - 备选模式下仍可对任一方案做「分派互换」人工微调：互换后该方案与其余每个方案的差异条数不得低于 N，会跌破 N 的候选自动排除并计入排除统计。
  - 硬约束
    1. **预指派**：显式指定的稿件—评审人对必定分配；
    2. **利益冲突**：声明冲突的稿件—评审人对绝不分配；
    3. **容量**：每位评审人承担稿件数 ≤ 其容量（含被预指派提前占用的名额）；
    4. **人数**：每篇稿件恰好分配到所需数量的、互不相同的评审人；
    5. **机构去重**：同一篇稿件对每个非空机构至多选择一人（机构按去首尾空白后的精确值判定、区分大小写；空机构仅代表本人，不与任何值合并）。
  - 优化目标（字典序）
    1. **主题匹配最大化**：优先把稿件分给擅长标签命中的评审人；
    2. **负载均衡**：在此基础上最小化评审人的最大负载。
  - 备选方案的求解方式：把每个已生成方案转写为一条 ILP 多样性切割
    `Σ(与旧方案重合的关系) ≤ 总名额 − ⌈N/2⌉`，与全部硬约束共同求解；若该整数规划不可行即停止并保留已有方案。
  - 可行性预检使用 Dinic 最大流（扣除预指派占用后的残量网络，含“论文→（论文,机构）槽→评审人”的机构层）；不可行时基于最小割给出**具体原因**：
    - 预指派问题（引用缺失 / 利益冲突 / **同稿机构重复** / 同篇超额 / 单人超容量，逐条列出稿件、机构与评审人）；
    - 单篇稿件可分配评审人数不足（含缺口数，机构去重同时计入）；
    - 全局容量不足（总名额缺口）；
    - 组合性瓶颈：哪一组稿件只能由哪几位评审人承担、缺口多少（Hall 条件违反的紧见证，机构名额一并计入）。
- **结果展示**：每个方案含逐篇稿件的分配明细与主题匹配标记、评审人负载进度条、匹配/负载统计、本地求解耗时；备选模式下以标签切换并在标签上对比匹配数、最大负载与相对方案 1 的差异条数。
- **分派互换（人工微调）**：在**成功且未过期**的「分配结果」页内提供「**分派互换（一换一）**」工具。
  - 选择两位**已有任务**的评审人后，枚举两人现有稿件之间的全部一换一候选；
  - 自动排除：**同稿**（两人对调后组合不变、还会造成同一稿件重复评审人）、交换后**触发利益冲突**、
    让**同一评审人重复承担同一稿件**、或让**同一稿件出现同一机构两位评审人**（机构去重硬约束）的项；剩余候选天然仍满足**每篇所需人数**与**个人容量**（一对一替换，每人承担数不变）；
  - 候选按「**主题匹配净变化**」从高到低排列，可预览交换前后的稿件、命中标签与总匹配数增减；
  - 确认互换后**只更新当前结果、不改动任何录入数据**，负载统计同步重算，结果标记为「**已人工调整**」；
  - 录入数据一旦变化，结果标记过期，互换工具暂停以防在过期方案上误改派；重新「生成分派」即恢复为原始最优方案并清除标记。
- **评审人缺席压力测试**：在顶部「**缺席压力测试**」标签页进入。
  - 仅在**当前数据可生成可行方案**时可运行；对每位容量 > 0 的评审人分别模拟**完全缺席**（容量临时置 0，预指派关系保持不变），
    使用与生成分派**完全相同的硬约束可行性逻辑**（Dinic 残量最大流）重新判定，**不改变录入数据或当前分配**。
  - 结果按「**仍可分配 / 不可分配**」两组汇总；每个不可分配场景必须给出：
    - **缺席者**；
    - **受影响稿件**：广义 Hall 缺陷稿件组，逐稿列出需求、缺席后剩余可选评审人数、单篇缺口；
    - **名额缺口**：组合性瓶颈缺口（Hall 紧见证）与全局剩余容量缺口两个口径——即使总容量仍充足，也能识别“调不开”的组合性瓶颈；
    - **可选评审人瓶颈**：见证评审人集合及其容量、对受影响稿件组至多能承担的名额，而不是只报总容量不足。
  - 录入数据（标题 / 需求 / 标签 / 评审人机构 / 容量 / 冲突）一旦变化，报告立即在标签页上标记**已过期**，重新运行后更新。
  - 支持**导出压力测试报告 JSON**。
- **数据持久化**：录入内容（含预指派关系）自动保存到 localStorage，刷新或关闭页面不丢失；沿用原存储键，旧版本数据（无预指派字段时补全为 `preAssignments: []`、评审人无机构字段时补全为空机构 `organization: ''`）读取时自动补全，无需迁移。
- **导出 JSON**：将**当前选中方案**的分配结果（含方案序号与差异统计 `solution`、稿件、评审人、**机构**、匹配标签、负载与利用率，以及 `manuallyAdjusted` / `swapCount` 人工调整标记、逐条 `preassigned` 标记与 `summary.preassignedCount`）下载为 JSON 文件；人工互换后导出的分派与统计均为调整后版本；压力测试报告亦可单独导出。
- 另附「载入示例」按钮，可快速体验。

## 一条命令启动（Docker Compose）

应用入口为页面顶部导航的四个标签页：**稿件（含预指派）**、**评审人 / 利益冲突**、**分配结果**、**缺席压力测试**。

在项目根目录执行**一条命令**即可完成构建与启动：

```bash
docker compose up -d --build
```

启动后在浏览器访问：

> **http://localhost:8080**

停止：

```bash
docker compose down
```

> 如宿主机的 8080 端口被占用，修改 `docker-compose.yml` 中 `"8080:80"` 的左侧端口即可。

## 本地开发（不用 Docker）

要求 Node.js ≥ 18。

```bash
npm install
npm run dev        # 开发服务器，访问 http://localhost:5173
```

生产构建与本地预览：

## 求解模型说明

对每个无冲突的（稿件 i，评审人 j）对设置 0/1 变量 `x[i][j]`：

- 约束：每篇稿件 `Σ_j x[i][j] = 需求_i`；每位评审人 `Σ_i x[i][j] ≤ 容量_j`；
- 冲突对不生成变量，因此天然不可能被分配；
- **机构去重**：对每篇稿件 i 与每个非空机构 o 增加 `Σ_{j∈org(o)} x[i][j] ≤ 1`；机构按去首尾空白后的精确值分组（区分大小写），空机构不生成该约束，故空值仅代表本人、互不合并；
- **预指派**：先逐条预检（引用存在、无冲突、**同篇机构不重复**、同篇不超名额、单人预占不超容量），通过后把对应变量用 `x[i][j] = 1` 的等式约束固定；
  可行性检验改在“残量”网络上进行——源→稿件容量为 `需求_i − 该篇预指派数`，评审人→汇容量为 `容量_j − 被预指派数`，
  预指派边视为已固定发送的流量不进入残量网；预指派占住的机构在该稿件上的机构槽一并封禁。残量最大流满流当且仅当全部硬约束（含预指派与机构去重）可同时满足；
- 目标采用**两阶段字典序优化**（避免直接引入 min-max 变量破坏全幺模性、拖慢整数分支）：
  1. **阶段一**：在真实容量下最大化 `Σ 命中主题的 x[i][j]`（预指派变量固定为 1、机构去重行约束生效）。该模型是带容量二部图匹配（b-匹配/运输问题）加机构分组约束，约束矩阵全幺模，LP 松弛的最优顶点解即为 0/1 整数解，求解器在根节点即可快速完成；
  2. **阶段二**：固定阶段一的最优匹配数不损失，对“评审人最大负载 L”做二分搜索（把所有评审人的容量上限临时改为 L 后重复阶段一），找到可行的最小 L，即实现负载均衡。

**备选方案模式**不改动上述硬约束与字典序目标，而是逐次求解：方案 1 为上述最优解；生成第 k 个方案时，对每个已生成方案加入一行多样性切割
`Σ_{(i,j)∈旧方案} x[i][j] ≤ T − ⌈N/2⌉`（T 为总分派条数），即与旧方案重合的关系不得超过 T−⌈N/2⌉ 条，等价于两方案关系对称差 ≥ N。带切割的模型仍为二元整数线性规划，由同一求解器按需整数分支求解；该模型不可行时即不存在满足全部多样性要求的第 k 个方案，停止生成并保留已找到的 k−1 个方案。预指派变量在每个方案中都固定为 1，天然包含在切割上界内，故实际可错开的只有自由关系（可实现上界 = 2 × 自由关系数）。

最大流网络在论文与评审人之间按稿件展开**机构槽**：`论文 i → 槽 (i,o) → 评审人 j`，论文→槽容量 1 实现“每篇每机构至多一人”，槽→成员评审人容量 1 且仅对无冲突者连边；空机构评审人走 `论文 i → 评审人 j` 直连边（容量 1），不经过任何共享机构节点，因此同一评审人跨多篇稿件承担不受影响、空机构之间也互不合并。

生成前先以 Dinic 最大流验证硬约束可行性：若不可行则不调用优化器，并通过最小割源侧集合定位瓶颈，给出可操作的修改提示。预指派预检不通过（含同稿机构重复）时直接失败，**不调用优化器、不产生部分结果**，并逐条返回具体稿件、机构、评审人与原因。

**缺席压力测试**不重新做目标优化：它把某位评审人的容量在临时数据副本中置 0（原录入数据与当前分配均不变，预指派关系保持不变），再次执行同一套硬约束评估。不可行时同样利用最小割源侧可达稿件集合作为广义 Hall 缺陷见证，输出受影响稿件、名额缺口（`剩余需求(Z) − Σ_j∈Y min(剩余容量_j, |Z 中与 j 有自由边的稿件数|)`，另附全局剩余容量缺口口径）与可选评审人瓶颈 Y。

## 目录结构

```
src/
  engine/
    alternatives.ts # 备选方案：关系对称差度量、差异上界与 N 参数校验
    maxflow.ts      # Dinic 最大流：硬约束可行性与瓶颈定位（残量网络含预指派占用 + 按稿件展开的机构槽去重）
    preassign.ts    # 预指派：逐条预检（引用/冲突/同稿机构重复/名额/容量）、失效关系派生、强制矩阵构建
    solver.ts       # 主流程 + ILP 建模（javascript-lp-solver，预指派变量固定为 1、每稿每机构 ≤1、备选方案多样性切割）；导出可复用的 evaluateHardConstraints、computeMatchedTags、solveAssignmentBatch
    stress.ts       # 评审人缺席压力测试：逐位容量置 0 后复用硬约束判定，输出 Hall 瓶颈诊断与数据指纹（含机构）
    swap.ts         # 分派互换（一换一）：枚举/校验/应用候选，排除同稿·冲突·重复·同机构·预指派·备选差异不足，按匹配净增排序
  components/
    PapersPanel.tsx # 稿件录入 + 每篇预指派编辑区（指定/移除、同机构提示）与失效预指派关系显式提示、逐条移除
    ReviewersPanel.tsx # 评审人录入（姓名/机构/容量/标签/利益冲突）
    StressPanel.tsx # 缺席压力测试面板（运行 / 过期提示 / 汇总 / 逐场景明细 / 导出）
    SwapTool.tsx    # 分派互换工具（选两位有任务评审人 / 候选预览 / 确认改派）
    …               # 录入与结果展示组件
  types.ts          # 数据模型（含预指派、预指派问题、压力测试报告类型、人工调整标记）
  storage.ts        # localStorage 持久化
  exporter.ts       # 分配结果 / 压力测试报告 JSON 导出
  sampleData.ts     # 示例数据
Dockerfile          # 多阶段构建：Node 构建 + nginx 静态托管
docker-compose.yml  # 一条命令启动（http://localhost:8080）
```
